# Захищені зони — не редагувати

## Контекст

`app/src/core/` належить платформній команді й працює в усіх клієнтських воркерах
агенції; зміни в ньому йдуть окремим PR через її рев'ю. Перевірка правил і матеріали
завдання — еталон, за яким оцінюється робота (`materials/architecture-brief.md`).

## Правило

- Не створюй, не редагуй, не видаляй і не перейменовуй файли в:
  - `app/src/core/**`
  - `app/scripts/**` (включно з `check-rules.mjs` і `core.lock.json`)
  - `materials/**`
  - `.coderabbit.yaml`
  - `.github/**`
- Жодних винятків: ні «дрібний фікс», ні «додам один тип», ні «задача цього потребує».
- Не перезаписуй lock-файл (`npm run check:rules -- --write-lock`) і не змінюй
  перевірку, щоб вона «пройшла».
- Не обходь захист: не копіюй код ядра в `integrations/` чи `sync/` і не
  перевизначай його типи локально.
- **Якщо задача не виконується без змін у захищеній зоні — зупинись.** Нічого не
  редагуй і опиши користувачу:
  1. який файл треба змінити і що саме (сигнатура / тип / поле);
  2. навіщо — яка частина задачі без цього не робиться;
  3. що можна зробити вже зараз без змін у core.

  Далі чекай рішення користувача: зміна core — окремий PR для платформної команди.

## Як перевірити

- `git status --short -- app/src/core app/scripts materials .coderabbit.yaml .github` → порожньо.
- `cd app && npm run check:rules` → рядок `core-untouched` дорівнює `0`.
