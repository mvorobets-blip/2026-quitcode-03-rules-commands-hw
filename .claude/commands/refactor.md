# Рефакторинг файлу

**Ціль:** $ARGUMENTS
(Якщо в рядку вище немає конкретного файлу — ціль вказана в повідомленні одразу
після назви команди. Немає й там — спитай і зупинись.)

## Кроки

1. Ціль у `app/src/core/**` чи іншій захищеній зоні — зупинись
   (`.claude/rules/do-not-touch.md`).
2. Прочитай файл, його тест (`<файл>.test.ts`) і модулі, які він імпортує або які
   імпортують його (напр. `app/src/integrations/index.ts`).
3. **До:** `cd app && npm test` і `npm run check:rules` — запиши кількість тестів,
   `TOTAL` і рядки для цього файлу.
4. Перепиши за `.claude/rules/conventions.md` і `.claude/rules/architecture.md`,
   використовуючи лише публічний API ядра зі списку в `architecture.md`.
5. Збережи все, що фіксують тести: URL, тіло запиту, тексти помилок, форму експорту
   (default / named). Зміна поля, яке перевіряє асерт, — зміна поведінки, так не можна.
6. **Після:** `npm test`, `npm run typecheck`, `npm run check:rules`.
7. Підсумок: таблиця «до → після» — порушення файлу за правилами, `TOTAL`, тести.

## Acceptance criteria

- [ ] У `check:rules` для цільового файлу 0 рядків. Не виходить без зміни поведінки —
      це Stop, а не «пояснений залишок».
- [ ] `TOTAL` зменшився рівно на кількість виправлених порушень файлу, нових немає.
- [ ] Усі наявні тести на місці й зелені (нові — лише додані, не замість старих);
      `npm run typecheck` без помилок.
- [ ] Діф — лише цільовий файл (і за потреби його імпорти поза захищеними зонами).

## Stop

- Змінюй лише цільовий файл і за потреби його імпорти поза захищеними зонами;
  `app/src/core/**` не чіпай.
- **Асерти в тестах не редагуй**, тести не видаляй і не пропускай (`skip`). Нові тести
  додавати можна — назви їх у підсумку.
- Не вдається зробити тести зеленими без зміни асертів чи core — відкоти свої правки й
  опиши, що саме заважає.
- Не комітить: покажи підсумок і чекай рішення людини.
